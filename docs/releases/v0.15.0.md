# Nexa Buyer Portal v0.15.0

Release record for workspace-aware buyer IAM and the Vue-aligned
buyer request flow over the canonical bounded contexts.

## Included

- BC-01 workspace preview and recognized-workspace gating before credential
  submission.
- Explicit two-factor challenge boundary for the buyer sign-in flow, with a
  deterministic mock code for local verification.
- Language switcher and sign-in interaction structure kept aligned with
  Platform while preserving the buyer-only route surface.
- Existing password request/reset flow connected to the API boundary.
- Catalog-owned request cart shared by catalog list, catalog detail and the
  four-step Request Builder; the Builder no longer invents a second product
  selector and routes empty carts back to Catalog.
- Buyer delivery step with saved/manual/current address handling, business-day
  date rules, server route preview and an embedded Google Maps route.
- Buyer-safe shell navigation and footer links for the implemented Portal
  surface, including Premium and Support routes.
- Design provenance synchronized to Nexa Design Lab `v1.0.2` (`main`, commit
  `04e2e4e`), with the consumer token checks bound to that source.

## Explicit boundary

No API, Blueprint or Vue source changed. No Portal organization-registration
flow was added because it is not present in the canonical Portal/Vue surface.
API mode remains the default. The current API contract has no second-factor
endpoint, so API mode reports capability unavailability after the password
step; mock mode verifies the challenge locally. Email delivery is backend-owned
and is not claimed by this frontend release.
Detailed Web acceptance criteria remain a governance gap: Blueprint marks the
Web catalog acceptance criteria as pending. This release claims audited
pre-design Flow parity for the implemented buyer slices, not 100% of the
pending Web catalog.
