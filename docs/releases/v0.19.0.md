# Nexa Buyer Portal v0.19.0

Release record for API-backed Buyer order and delivery continuity.

## Included

- Buyer Sales Order cards now use line quantities and the existing delivery
  projection for route and temperature status.
- Delivery mapping preserves `clientAccountId`, nested route assignment,
  temperature bounds, temperature status, POD status and API alerts.
- Delivery and Business Document projection failures are surfaced as partial
  data so an empty fallback is not mistaken for authoritative absence.
- Notification action failures remain visible through the localized Portal
  shell and notification page treatment.

## Surface boundary

The Portal remains a Buyer surface. Internal role separation belongs to
Platform and the API:

| Internal role / capability | Owning surface |
|---|---|
| `COMPANY_OWNER` | Platform executive overview |
| `SALES` | Platform commercial workspace |
| `WAREHOUSE` | Platform inventory workspace |
| `LOGISTICS` / Dispatch | Platform dispatch and fulfillment workspace |

Dispatch is a capability of canonical `LOGISTICS`; no separate Dispatch role
is introduced. `BOM` remains `OPEN`/`DEFERRED` because no accepted contract
defines its role or lifecycle.

## Explicit boundary

- No new endpoint, entity, state, role or business rule was invented.
- API, Blueprint, Design Lab and Vue/legacy sources were not modified.
- Mock adapters remain available only for explicit `nexaDataMode=mock`; API is
  the default runtime mode.

## Validation

- Portal unit suite: 127 tests across 63 files.
- Design Lab v1.0.2 foundation, catalog asset and bounded-context validators.
- Production build passed; existing bundle/style budget warnings remain
  non-blocking.
- Authenticated Buyer canonical E2E against Docker: desktop and mobile 2/2.
- `npm audit --omit=dev`: 0 vulnerabilities.
