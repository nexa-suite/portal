# Nexa Buyer Portal v0.14.0

Local release preparation for executable buyer slices over the canonical
bounded contexts.

## Summary

The Buyer Portal now supports an explicit runtime `mock` mode for deterministic
`generic` and `icisa` buyer demonstrations. `api` remains the default mode and
existing buyer routes and REST contracts are preserved.

## Included

- BC-01 Buyer sign-in/session bootstrap, profile and workspace preview for both
  demo profiles.
- BC-02 buyer account and address reads.
- BC-03 buyer-safe catalog and pricing preview.
- BC-04 canonical purchase-request draft, four-step review, submit, list,
  detail, sales orders and order downloads with in-memory versioned state.
- BC-06 delivery tracking; BC-07/BC-08 receivables, payment history, bank
  transfer reporting and a local Payment Element double.
- BC-09 buyer-visible documents/evidence and BC-10 notifications.
- Offline no-op change-feed adapter in mock mode; the existing SSE stream is
  retained for API mode.
- Functional baseline, mock-mode guidance and executable adapter tests.

## Explicit boundary

This release does not change the API, Blueprint or canonical bounded-context
definitions. Mock state is an in-memory buyer-safe fixture and does not replace
backend persistence, authorization, jobs or webhooks. The release is a PRE-V1
functional foundation, not a claim of complete product migration or Production
Readiness.
