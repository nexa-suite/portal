# Nexa Portal v0.26.0

Date: 2026-08-29

## Summary

API-only production composition for the Buyer Portal.

## Included

- Production bootstrap and feature routes bind the existing HTTP clients
  directly to the application ports for authentication, security, change feed,
  notifications, payments, catalog, buyer account, purchase requests, sales
  orders, deliveries, receivables and business documents.
- Browser runtime no longer imports the mock data-mode provider composition.
- Notifications production wiring uses the canonical `NotificationsApiPort`,
  with regression coverage for the provider binding.

## Architecture and boundary

- Portal remains Buyer-only. Platform roles and Dispatch remain Platform
  permission concerns.
- Existing application ports, HTTP clients and API contracts remain the
  boundaries; no endpoint, entity, state, persistence model, dependency or
  cross-context contract was introduced.
- `BOM` remains `OPEN`/`DEFERRED` because no accepted role, endpoint, entity or
  lifecycle contract exists.
- Mock adapters remain available only for isolated tests; they are not a
  browser-runtime data source.

## Verification

- `npm test -- --no-progress`: 67 files, 136 tests passed.
- `npm run build`: passed; existing bundle/style budget warnings remain
  non-blocking.
- Browser E2E: 16/16 passed locally against an isolated API runtime and in the
  mandatory CI verification job.
- `npm audit --omit=dev`: 0 vulnerabilities.
- Design Lab v1.0.2 foundation, catalog-asset and bounded-context validators
  passed.
- Pull request #59 CodeQL, analyze and both CI verification jobs passed.

## Known limitations

- This is a focused Portal increment. It does not certify 100% product or
  pixel parity across every legacy surface.
- Existing SCSS/component budget warnings remain for later focused maintenance.
- The current local PostgreSQL/API environment has migration-checksum drift;
  this release did not mutate that existing database state.

## Release impact

- Portal version: `0.26.0`.
- Release follows repository GitFlow: feature branch → develop → release
  branch → main → annotated tag → GitHub Release → back-merge.
