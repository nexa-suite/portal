# Nexa Buyer Portal v0.5.0

## Summary

Consolidated previously unreleased Identity, tenant, security and commercial vertical work. Intermediate planned versions were never published.

## Highlights

- Buyer authentication and secured Catalog discovery/detail.
- Request Builder, My Requests and Request Detail with server-backed snapshots and typed forms.
- Dynamic request and catalog aliases preserve identifiers; touched surfaces retain the Vue-derived structure.

## Functional capabilities

- Add catalog items to a draft, update quantities, remove lines, choose delivery/payment data, save and submit.
- List and filter own Purchase Requests, open detail, resume draft, respond to adjustment, resubmit and cancel.

## Architecture

- Buyer Sales Application facades, Domain models, API clients and Presentation pages remain feature-local.
- Catalog and Sales routes load lazily; API response DTOs are mapped before reaching Presentation.

## Security

- Portal surface and Buyer role guards reject internal roles; API enforces tenant, workspace, client-account and lifecycle authority.
- Session state stays in memory and browser storage is not used for access or refresh tokens.

## UI changes

- Consolidated Request Builder, My Requests and Request Detail states with loading, empty, error and retry feedback.
- Structural parity has been advanced for implemented surfaces. Final decorative and pixel-level parity remains ongoing.

## Database migrations

None in this frontend repository; API `v0.6.0` owns the persistence contract.

## Docker

Modern Compose serves the optimized production build on `127.0.0.1:4300`; Legacy Vue remains a separate reference runtime.

## Validation

- `npm run validate:catalog-assets`.
- `npm test`.
- `npm run build` with no bundle-budget warning.
- `npm audit --omit=dev` and browser route checks.

## Breaking changes

Dynamic request and catalog aliases now preserve concrete route identifiers during navigation.

## Upgrade notes

Run `npm ci`, validate catalog assets, test and build before serving the static output. Use the API release for backend contract changes.

## Known limitations

- No Sales Order persistence or HTTP workflow.
- No inventory reservation.
- No dispatch.
- No invoicing.
- No cache tier.
- No production deployment.
- Final pixel-level Vue parity remains ongoing.
