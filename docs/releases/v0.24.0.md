# Portal v0.24.0

## Summary

Design Lab-aligned Buyer Catalog and accessible cart quantity interaction.

## Why

The existing Buyer Catalog had the correct API-backed direction but drifted from
the executable Nexa Design Lab and the historical Vue product-card composition:
raw text symbols were used for actions, media fallback was ambiguous, the
responsive grid could overflow at intermediate widths, and selected products
could only be toggled rather than adjusted by quantity.

## Scope

- Align Catalog list and detail presentation with the Design Lab v1.0.2 tokens,
  public visual language and Vue reference flow.
- Keep the authorized catalog, cold-chain status, offer status and server pricing
  visible on each product card.
- Add a keyboard-accessible cart stepper with explicit add, decrement and remove
  behavior.
- Add resilient product-image fallbacks and canonical Nexa icon usage.
- Preserve responsive behavior from desktop through 390 px without horizontal
  overflow.

## Architecture impact

- No new endpoint, entity, state or dependency.
- Existing `CatalogQueryService`, `CatalogApiClient` and
  `PortalCatalogCartFacade` remain the application boundaries.
- The browser cart remains presentation/draft interaction state; inventory,
  reservation and pricing truth remain server-owned.

## Security and tenant impact

- No authentication, authorization or tenant predicate changed.
- The Portal remains Buyer-only and does not expose Platform role controls.
- Product availability is rendered from the existing catalog contract; the
  frontend does not manufacture quantities or reservations.
